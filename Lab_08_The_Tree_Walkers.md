### 🌳 The Mission
Somewhere beneath a database server humming in a USI server closet, a search engine has been asked to find one specific record among 50 million rows — and it needs an answer before the user's coffee gets cold. Scanning the table row-by-row would take an eternity; instead, the engine walks a **Binary Search Tree (BST)** index, discarding half the remaining records with every step. Your task is to give the engine's index a voice: implement a BST search, the three classic recursive traversals, and teach the tree to describe its own shape by serializing itself to JSON.

### Part A: The Proof Detective (50 Points)
**Instructions:** Answer the following questions in a separate document (PDF or Markdown). Show calculations and traces for Questions 1 and 2, explain your reasoning for Question 4, and write a formal inductive proof with an explicit base case and inductive step for Question 3.

1. **The Log-Time Dilemma:**
   A poorly indexed table of 10,000,000 records requires a full linear scan (`O(n)`) to find a record in the worst case.
   - How many comparisons, worst case, does the linear scan need?
   - If that same data is indexed in a balanced BST, how many comparisons, worst case, does a search need (`O(log n)`)?
   - At roughly 1 million comparisons per second, express the real-world time difference in a single sentence a non-technical manager would understand.
2. **Visual Tracing:**
   Insert the following keys into an empty BST, **in order**: `50, 25, 75, 10, 30, 60, 80, 5`.
   - Draw the resulting tree.
   - Write out the sequence of keys produced by an **Inorder**, a **Preorder**, and a **Postorder** traversal.
3. **Maximum Height Bound Proof:**
   Prove by induction that, in the worst case (a fully degenerate, "linked-list-shaped" tree), a BST storing `n` nodes has height `n - 1`.

   > [!CAUTION]
   > **The Brutality Clause:** This is a recursive/inductive proof problem. Any proof missing an explicitly stated base case receives an automatic **0** on that question, regardless of the correctness of the inductive step.
4. **PDC Reasoning:**
   Two threads are given read-only access to the same BST at the same time: one is running an Inorder traversal for a report, and the other is searching for a single key. Is this safe without any locks? Now suppose a third thread wants to **insert** a new node while the other two are running. What could go wrong, and where would you place a lock to prevent it?

### Part B: The Recursive Coder (50 Points)
**Instructions:** Complete the `search`, `inorder`, `preorder`, `postorder`, and `to_json` methods in the provided `serialize_tree.py`.

**Requirements:**
1. `search(root, target)` must be implemented **recursively**, returning the `TreeNode` containing `target` if it exists, or `None` if it does not. It must correctly exploit the BST property (only recurse into the subtree that could possibly contain `target`, never both).
2. `inorder`, `preorder`, and `postorder` must each return a Python list of keys in the correct traversal order.
3. `to_json` must recursively build a nested dictionary of the form `{"key": <value>, "left": <subtree or null>, "right": <subtree or null>}` and print it to the terminal via `json.dumps(..., indent=2)`.
4. **Base Case Required:** Every recursive method must correctly handle an empty subtree (`None`). Remember the **Brutality Clause** — a recursive method with no base case is an automatic 0.
5. **Verification:** Run the script using `python serialize_tree.py`. If you see the "Success Token," your implementation is correct.
